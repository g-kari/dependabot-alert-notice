# Go 実装ルール

このファイルは `internal/` 配下の Go コードに適用する。ルートの `AGENTS.md` と併せて守る。

## 品質

- 変更後はルートで `scripts/check.ps1` を実行する。
- エラーには処理の文脈を付け、`fmt.Errorf("処理名: %w", err)` の形でラップする。
- エラーを黙って捨てない。クリーンアップ時に意図して無視する場合だけ `_ = resource.Close()` を許容する。
- ログは `log/slog` を使い、検索可能なキー付きの構造化ログにする。
- exported な型・関数には名前から始まる Go doc コメントを付ける。
- 標準ライブラリを優先し、新しい依存関係を追加する前に必要性を確認する。

## 並行処理とリソース

- 共有データは既存の `sync.RWMutex` パターンに合わせて保護する。
- goroutine には可能な限り `context.Context` を伝播する。
- goroutine 内のエラーを黙って捨てない。
- DB、HTTP body、rows、ファイル、テストサーバーなど、明示的に閉じられるリソースは確実に閉じる。

## 外部連携

- `gh`、`claude`、Slack、Discord などは利用側で定義した小さなインターフェース越しに扱う。
- テストでは実行関数の差し替え、モック、`httptest` を使う。
- OS 固有のパスを文字列連結で作らず、`filepath.Join` を使う。
- シェル固有の前提を追加する場合は Windows と Devbox の双方への影響を確認する。

## テスト

- テスト名は対象と期待動作が分かる名前にする。
- テーブル駆動テストを使う場合、失敗メッセージには入力と期待値を含める。
- Web ハンドラーには `httptest.NewRecorder` / `httptest.NewRequest` を使う。
- 永続化テストでは一時ファイルを使い、DB 接続を cleanup で閉じる。
